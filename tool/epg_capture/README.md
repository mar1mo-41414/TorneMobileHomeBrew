# EPG 採取キット (BS 番組表のジャンル色検証 / CS 番組表対応のための採取用)

torne mobile HB の番組表のためのデータ採取キットです。衛星 (BS/CS) が
受信できる環境から、nasne が配信する番組表 (EPG) データをそのまま
採取して送り返してもらうためのものです。目的は次の 2 つです。

- BS の番組タイルにジャンル色が付くかどうかを検証する
- CS の番組表対応に必要となる、CS の EPG 版数表の実物を採取する

## 何を確かめるためのデータか (BS ジャンル色の検証)

放送波としての BS の EIT にジャンル情報 (ARIB STD-B10 の content
descriptor) が含まれることは、規格と既存の EPG 実装から確定しています。
不明なのは次の 3 段で、採取データは主に 1 と 2 を確定させるためのものです。

1. nasne が配信する EPG ペイロードに、content descriptor が残っているか
2. アプリのパーサが、BS (衛星) 経路でその descriptor を拾えているか
3. 番組表グリッドが実際にジャンル色を塗るか

スクリプトの実行サマリが 1 の一次回答になります (「ジャンル有」の件数)。
2 は、送ってもらった EIT バイナリをこちらでアプリのパーサに通して
検証します。3 は、アプリの BS 番組表グリッドのスクリーンショットと
突き合わせて確認します。

## 何を確かめるためのデータか (CS 番組表の対応)

torne mobile HB の番組表は現在、地デジと BS のみに対応していて、CS は
未対応です。CS に対応するには、CS の版数表に現れるレコードの flags の
分布とレコード長を実物で確定させる必要があります (CS の版数表には
BS とは異なる flags のレコードが混ざると見込まれています)。

このキットの既定の実行 (衛星バンド、broadcastingType=3) では、BS と
CS のサービスが両方とも対象になり、**版数表は機体からの応答そのまま
全量が `epg_version_table_type3.bin` に保存されます**。CS だけを
分離して取る必要はなく、CS が受信できる環境で既定のまま実行して
もらえれば、そのファイルが CS 対応のための解析材料 (フィクスチャ)
になります。

## 前提

- BS/CS が受信でき、チャンネル設定が済んだ nasne が LAN にあること
  (番組表データが機体に蓄積されている状態。設定直後はデータが
  揃っていないことがあります)
- PC に Python 3 (3.8 以降) が入っていること。追加のインストールは
  不要で、標準ライブラリだけで動きます
- PC が nasne と同じ LAN にいること

## 実行手順

このフォルダ (`tool/epg_capture/`) で:

```
python3 capture_epg.py <nasne の IP アドレス>
```

- 例: `python3 capture_epg.py 192.168.1.10`
- 既定では衛星バンド (broadcastingType=3、BS/CS) を取得します。
  CS の採取もこの既定のままで構いません (BS/CS は分離されず、
  衛星バンドとしてまとめて取得されます)。
  地デジ (broadcastingType=2) を取る場合は `--type 2` を付けます
- 保存先を変える場合は `--outdir <フォルダ>` を指定します
  (既定は `epg_capture_out/`)

実行すると画面にサマリ (取得できたサービス数、イベント数、うち
ジャンルを持つイベント数と内訳) が表示され、`epg_capture_out/`
フォルダにデータ一式とサマリが保存されます。

## 生成されるファイル

| ファイル | 内容 |
| --- | --- |
| `channels_type3.json` | 機体のチャンネル一覧 (WebAPI の応答そのまま) |
| `epg_version_table_type3.bin` | EPG 版数表 (EPGVersionInfoGet の応答そのまま、バイナリ全量) |
| `epg_get_request_type3.bin` | 送信した EPGGet リクエストボディ |
| `epg_get_response_type3.raw` | EPGGet の応答 (XOR 難読化のままの生データ) |
| `epg_eit_type3.bin` | 応答を復号 (XOR 解除 + zlib 展開) した EIT セクション連結 |
| `summary_type3.txt` | 実行サマリ (画面表示と同じ内容) |

(地デジの場合は `type3` の部分が `type2` になります。)

CS の採取では、特に `epg_version_table_type3.bin` (版数表の全量) が
解析の要になります。欠かさずに含めてください。

## 送り返してほしいもの

1. `epg_capture_out/` フォルダ一式 (zip 等にまとめて)
2. BS ジャンル色の検証が目的の場合のみ、torne mobile HB の
   **BS 番組表グリッドのスクリーンショット 1 枚**
   (採取とできるだけ近い時間帯のもの。ジャンル色が付いているように
   見えるかどうかが分かる画面)。CS の採取ではスクリーンショットは
   不要で、フォルダ一式だけで構いません

## 注意点 (版数表と EPGGet の対象について)

- スクリプトが EPGGet の対象サービスを選ぶ際、版数表を固定長
  (144 バイト) のストライドで歩く方式を使っています。短いレコード
  (76 バイトや 8 バイト) が混ざる版数表では、それより後ろにある
  サービスが EPGGet の対象から漏れることがあり、その場合は
  `epg_eit_type3.bin` やサマリに全サービス分が含まれないことが
  あります
- ただし、**版数表バイナリ (`epg_version_table_type3.bin`) 自体は
  応答そのまま完全な形で保存されます**。CS の版数表の解析には
  このファイルがあれば足りるので、上記の漏れは CS 採取の支障には
  なりません

## 取得の仕組みと安全性

- スクリプトはアプリと同一の経路で取得します:
  チャンネル一覧と EPG 版数表 (GET) → リクエストボディの組み立て →
  `chEpg/EPGGet` への POST → 応答の XOR 0x9d 解除と zlib 展開
- EPGGet には X-DTVToken ヘッダーが必要です。トークンはアプリと
  同じく、機体の MAC アドレス (`status/networkIfInfoGet` の応答から
  取得) の下 3 オクテットを PIN として導出します。パスワード等の
  資格情報は扱いません
- すべて読み取り専用の取得で、機体の設定変更や録画への影響は
  ありません
